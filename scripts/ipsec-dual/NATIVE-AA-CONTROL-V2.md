# Native operator V2 control plane (opt-in, packet gate DENY ONLY)

The `native.py` operator accepts `--aa-config /absolute/private/config.json`. Without it no AA connection, signer, or journal is opened. This does **not** authorize packets: each operator loop calls `topology.authorize(0)` even after an `ATTESTED` control-plane decision and even on errors. The synthetic lab path is unchanged. Do not enable a packet gate based on these tests.

Configuration is an owner-owned 0600 regular file under a real owner-owned 0700 directory. Exact JSON keys: `directory` (0700 owner-owned private spool/journal), `operatorKey`, `nodeKey`, `aaKey` (distinct pinned 32-byte Ed25519 public keys as lowercase hex), `supervisorKey` (private 0600 PKCS8 PEM pathname), `url` (explicit `https://HOST/v2/authorization/attest`), `ca`, `cert`, `tlsKey` (explicit mTLS trust/custody paths), and `resource` (e.g. `tcp:10.80.0.2:8080`). No URL, keys, certificates or private spool location are defaulted. Supply a node mTLS certificate whose raw Ed25519 public key equals `nodeKey`, and configure the AA's distinct operator certificate pin and response signing key. Protect private key and config paths with deployment custody and ownership controls; never put secrets in repository configuration.

`directory/challenge.json` is an atomically written supervisor-signed challenge scoped to the *real* kernel boot UUID, freshly random supervisor session, service, nodes, resource and nonce. The operator signs an admission `RECOVER` (or `REVOKE`) operation in canonical `operation_bytes` form and publishes `{"operation": ..., "signature": "base64..."}` in `directory/inbox.json` by writing a 0600 temporary file in the same directory and atomically renaming it. After recovery, read the **new** challenge, and have `NativePolicyExporter.issueApproved` explicitly issue a signed Java V2 envelope with original `CLOCK_BOOTTIME` issue/deadline (maximum three seconds). Submit `{"envelope": ...}` through the same private atomic spool. Supervisor requires distinct operator and node signatures and durable admission journal commit before it asks AA via hostname-checked mTLS. The AA `scope` is SHA-256 of ASCII `DEFENDERLINK-NATIVE-AA-SCOPE-V2\n` followed by `serviceId=...\nclientNodeId=...\nownerNodeId=...\nresource=...\n` in that order, not merely the service ID; provision operator AA transitions for exactly this derived scope. It maps the kernel UUID to 32 lowercase hex for AA `bootId`; each AA request has a new random 128-bit challenge and the same boot/session/full derived scope, while the original native approval nonce remains locally bound to the signed V2 envelope. AA generation/epoch/revocation floors are independent from the native admission generation. Only the node TLS identity pinned at AA can request attestation. AA signed response must match its fresh attestation challenge, boot, session, node and derived full scope; the independent native approval nonce is checked against the Java-signed envelope. The response key is independently pinned, then the floors are written to `aa-highwater.json` before an informational `ATTESTED` result. Both original BOOTTIME expiry and AA wall-clock expiry bound the decision.

All files in the private directory must be owner-owned regular 0600 files with one link. The reader uses `O_NOFOLLOW`, inode and size checks, rejects duplicate JSON fields, and refuses unsafe entries. No HTTP ingress route is exposed by the supervisor. Local writer and supervisor share the same host uid only inside an approved isolated deployment; restrict the spool directory to trusted local principals. The inbox is not deleted automatically: stale submissions fail nonce/generation checks; replace atomically for each request. On every supervisor restart the session changes and admission is denied until a newly signed recovery and fresh grant. An AA restart quarantines its state until its own independently authenticated operator recovery/reauthorization. Missing, corrupt, unsafe, or regressed AA highwater denies; local files and SQLite do **not** establish rollback resistance against a full consistent restore, and there is no external monotonic anchor or TPM here. Negative controls confirm that an already delivered AA attestation remains informationally `ATTESTED` immediately after AA revocation or outage until re-attestation or the original native grant deadline (at most three seconds from issuance under V2); the Java harness forces re-attestation to demonstrate denial. This is not instantaneous revocation or proof of a packet denial bound, and must be solved before any traffic gate connection.

Verification without privileges: `/usr/bin/python3 -m unittest discover -s scripts/ipsec-dual -p 'test_*.py' -q` and `mvn -B -q test` from an isolated worktree. The Python tests drive a loopback ephemeral-PKI AA server, actual mTLS and supervisor ingress with synthetic signing keys. `NativeControlAaIntegrationTest` additionally drives real `NativePolicyExporter.issueApproved` → private JSON-lines spool → mTLS AA → native operator control decision in one JUnit/Python lifecycle, including expiry, forced revocation re-attestation, restart and outage; it asserts packet denial throughout. `Dockerfile` adds Debian `python3-cryptography`; an isolated image build and `--network none` test run proved in-image import and all 141 Python tests passed for the pre-Java-harness source snapshot. No privileged namespace deployment was performed. No production PKI, independently protected host rollback anchor, instantaneous revocation or protected packet acceptance is claimed.
