# Admission V2 — disconnected Stage 1–3 slice (not deployment acceptance)

**No packet gate is installed.** `native.py` and the scheduled Java `refresh()` remain deny-only. These are explicit control-plane library APIs, not an HTTP endpoint or a production authorization path. Do not treat a returned `AUTHORIZED` state as permission to route traffic. No actual operator identity, supervisor key, or privileged networking is configured here.

## Trust and protocol

Provision three *distinct*, separately pinned Ed25519 public keys: an external human operator key, a supervisor challenge key, and the owner node key. The operator private key must remain outside the service and supervisor. Obtain boot ID from the trusted current kernel boot identity and `now_ns` from the receiver's `CLOCK_BOOTTIME`; choose a new unpredictable supervisor session ID for each supervisor start. The supervisor must issue the challenge only for this current boot/session and exact pinned service/client/owner/resource. It signs `challenge_bytes(challenge)`; the nonce alone **is not approval**. A local authenticated transport to transfer the challenge, detached operator signature, and Java issuance result is a deployment prerequisite and **has not been wired**. Never expose this entry point as unauthenticated HTTP.

Initialize `Admission(journal_path, operator_public, node_public, supervisor_public, trusted_scope, session_id)` in one private supervisor process. Use `challenge(supervisor_signer, now_ns)` to get a signed current-session challenge. For absent, damaged, rebooted or restarted state, ask the human operator to sign `operation_bytes(op)` with action `RECOVER`, a generation greater than the journal floor, and fields matching the current challenge. Pass it to `apply_operation`. Recovery only enters `PENDING_FRESH_APPROVAL`; it **never grants**. After a **new** challenge, have the human sign the exact Java `NativeIssuanceV2.canonical(payload)` for action allow. `NativePolicyExporter.issueApproved(...)` checks the pinned supervisor challenge and independently verifies that operator signature before node countersigning. Its envelope can be passed to `Admission.accept(envelope, now_ns)`. Generation must increase, issuance ID must be unused, and signed boot, nonce, scope and short fixed boottime deadline must match. `state(now_ns)` reports `DENIED`, `PENDING_FRESH_APPROVAL`, `AUTHORIZED`, `EXPIRED`, or `REVOKED`; only in-process validated grants may be `AUTHORIZED`.

Revoke is **not** an allow envelope: sign `operation_bytes(op)` with action `REVOKE`, a newly issued challenge and strictly higher generation, then call `apply_operation`. A duplicate or altered operation is rejected. Following revoke, a separate signed `RECOVER` and new signed allow are required. Files are private regular files with append+fsync and parent fsync on create. Damaged journal files are archived before signed recovery, not trusted or silently promoted. Run as a single owner process with a private owner-only directory; do not run two writers. Failures in journal write, signature, clock monotonicity or replay return deny.

## Hard safety boundary / blocker

A local hash-chained, fsynced file is **not** an external monotonic anchor. A privileged attacker or disk rollback can replace the *entire* journal with an internally consistent old copy, including lower generation and revocation history. This cannot be detected reliably by these libraries. They intentionally quarantine every supervisor restart/reboot and demand a **new signed operator recovery approval and then a new signed allow**; old persisted grants are never reactivated. This assumes the operator key is uncompromised, boot/session and secure random nonce are fresh, the pinned supervisor key is controlled outside untrusted callers, the disk directory and process are isolated, the owner checks actual kernel boot time, and the operator can distinguish a genuine recovery request from an attacker-induced one. Even with those assumptions this is **not durable rollback resistance / production PASS**. An independent durable monotonic anchor, robust key custody and authenticated operator UI, durable multi-process coordination, end-to-end admission wiring and a separately designed packet gate would need independent review before activation. Keep production traffic denied.

Test with `/usr/bin/python3 -m unittest discover -s scripts/ipsec-dual -p 'test_*.py'` and `mvn -q clean -Dtest=NativeIssuanceV2Test,NativePolicyExporterTest test`. A JUnit test passes an actual Java-exported, separately operator-approved envelope and signed recovery challenge into the Python `Admission` state machine, observes `PENDING_FRESH_APPROVAL -> AUTHORIZED -> EXPIRED`, and runs entirely with ephemeral test keys and private temporary journals. It is not a live JVM/supervisor deployment or packet proof; no live credentials are used.
